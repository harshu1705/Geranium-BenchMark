2. Backups and Recovery
Q: Are backups kept segregated from the primary network (offline or immutable)?
A: Yes. We use Veeam immutable storage in AWS S3 with Object Lock enabled for 30 days. On-premise backups are segregated on a separate VLAN with unique credentials.
Q: How often are backups tested for full restoration capability?
A: We perform a full bare-metal restore test quarterly. The last test was successful on July 10, 2026, where we successfully restored the primary ERP database within 4 hours.
Q: Are backups encrypted both at rest and in transit?
A: Yes. All backups are encrypted using AES-256 at rest and TLS 1.2+ in transit. Keys are managed in a dedicated AWS KMS vault.

A: No, not 100%. We deploy CrowdStrike Falcon on all servers and 98% of workstations. The remaining 2% are legacy ruggedized barcode scanners in the warehouses that cannot run the agent due to OS incompatibility.

A: We perform automated internal scans weekly and external perimeter scans monthly.
Q: Do you conduct annual third-party penetration testing?
A: Yes. We engage a third-party firm annually to conduct a grey-box penetration test of our external perimeter and primary web applications. The last test was in April 2026.

A: Yes. All corporate and retail store managers must complete a 1-hour security training module annually. Warehouse staff and cashiers receive a 15-minute briefing.

Cyber Liability Underwriting Guidelines (v2.1)
1. Purpose and Scope
This document outlines the standard underwriting rules, base rates, and authority limits for the placement of Commercial Cyber Liability insurance. These guidelines apply to all retail, manufacturing, and professional services risks with annual revenues between $50M and $1B. Adherence to these guidelines is mandatory for all underwriters. Any deviation requires formal VP approval. The purpose of this framework is to ensure consistent pricing and strict risk selection criteria in a hardening cyber insurance market.
The scope of this document covers First-Party Business Interruption, Ransomware Extortion, Third-Party Privacy Liability, and Regulatory Fines. It does not cover Technology Errors & Omissions (Tech E&O), which must be underwritten separately.
2. Definitions
• Base Premium: The initial premium calculated solely based on the applicant's annual revenue.
• Loss Run Surcharge: A penalty multiplier applied to the base premium based on historical claims.
• Security Surcharge: A penalty multiplier applied due to missing critical security controls.
• Authority Limit: The maximum policy limit an underwriter is authorized to offer without executive referral.
• MFA: Multi-Factor Authentication, required for all remote access and privileged accounts.
3. Base Rate Calculation
The base premium is calculated strictly on the applicant's most recent annual revenue. The base rate for the Retail sector is $0.05 per $1,000 of annual revenue. For example, a retail risk with $100,000,000 in revenue would generate a base premium of $5,000. This base premium serves as the starting point before any surcharges or credits are applied.
4. Loss Run Surcharge Rules
Historical claims indicate a higher propensity for future losses. Underwriters must review the last 5 years of loss runs.
• Clean history (0 claims): 0.90x multiplier (10% credit).
• Minor claims (Totaling under $100k in last 3 years): 1.00x multiplier (Neutral).
• Moderate claims (Totaling $100k - $499k in last 3 years): 1.10x multiplier.
• Severe claims (Totaling $500k or more in the last 3 years): 1.20x multiplier.
• Any single claim >$1M: Automatic Decline.
5. Ransomware & Security Controls
Ransomware is our leading source of severity loss. We enforce strict minimum security requirements.
• MFA on all Employee Email: Mandatory. If missing, Decline.
• MFA on all privileged/admin accounts: Mandatory. If missing, Decline.
• MFA on all Third-Party/Contractor Remote Access (VPN/RDP): If missing, the maximum policy limit is capped at $10,000,000, and a 1.25x security surcharge multiplier must be applied to the premium.
• Endpoint Detection & Response (EDR): Required for all endpoints. If missing, Decline.
6. External Security Scans
All applicants requesting >$5M limits must undergo a Third-Party Perimeter Security Scan.
• Critical Vulnerabilities (CVSS > 9.0): If any Critical CVEs are identified on the perimeter scan, the policy cannot be bound clean. It must either be Declined OR conditionally approved with a Subjectivity Clause requiring remediation within 15 days of binding.
• High Vulnerabilities: Must be patched within 30 days.
• Medium/Low: Accepted as normal business risk.
7. Final Premium & Authority Limits
The Final Premium is calculated by multiplying the Base Premium by the Loss Run Surcharge and the Security Surcharge. (Final Premium = Base Premium × Loss Run Multiplier × Security Multiplier). Surcharges stack multiplicatively.
Authority Limits:
• Underwriter I: $5,000,000
• Senior Underwriter: $15,000,000 (Subject to security caps)
• VP Underwriting: $25,000,000
8. Escalation Protocols
If a risk triggers multiple Decline conditions, the file must be closed immediately. Do not refer to VP. If the broker pushes back, document the specific guideline violations in the file and inform the Regional Director.
