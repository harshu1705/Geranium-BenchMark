P42 [Normal] STRESS-003 — Memory Threshold Breach (PASS with caveat): The Bulk PII Export scenario is recorded in the workbook with a status of “PASS*” — a qualified pass, not a clean one, and the qualification matters. Its declared SLA metric is throughput, and throughput is comfortably met at every percentile (680 / 620 / 540 records per minute against a ≥500 records/min threshold), so §4.5.a and §4.5.b are both satisfied for this scenario. The Resource Utilization data for the same run, however, records a peak memory figure of 3.36 GB against a 3.0 GB memory threshold — an overage of 0.36 GB, or 112% of the permitted ceiling — and notes that the resident set did not return to its pre-run baseline after the run completed. That signature (sustained growth over a 180-minute window, no return to baseline) matches VULN-0044, “Memory leak during bulk PII export under sustained load” (Major, module Bulk PII Export), whose own scan note records a linkage to a performance-benchmark memory threshold breach occurring only after roughly two hours of continuous export. STRESS-003 therefore did not pass cleanly: the throughput envelope holds while the resource envelope does not. This is material rather than cosmetic, because bulk PII export is precisely the workload that processes GDPR-regulated personal data at volume, and it was measured on an environment already below the §4.5.c capacity floor — production headroom will be tighter, not looser. VULN-0044 must be fixed and STRESS-003 re-run before bulk PII export is operated at production volume.

P44 [Normal] ⚠ Source Limitation — Capacity Calculation Methodology: The individual component ratios listed in the Environment Specs sheet are: CPU Cores 50%, RAM 50%, Storage IOPS 50%, Network Bandwidth 10%, Database Instance ~50%, Application Servers 50%, Load Balancer 'Simplified.'
